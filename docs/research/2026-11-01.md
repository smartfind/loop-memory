## Window summary

Two releases dominated this window, and both are about **score
integrity and honest measurement** rather than new surface area.

**agentmemory v0.9.31** fixed a prefix-score inflation bug in its
keyword ranking and reported the delta on a deterministic benchmark:
strict recall-all@5 went from **65.74 % to 84.68 %** (+18.94
points), with complete-evidence retrieval rising from 309 to 398 of
470 answerable questions — 92 recovered, 3 regressed. The release
note is careful about what the number means: *"component retrieval
results on inspected development data, not held-out answer accuracy or
a release-wide speed benchmark."* The bug itself was a scoring
mistake in the *prefix-expansion* path: a document that matched a
query exactly was counted again among the prefix matches, so its
score was inflated several times over. The fix makes exact hits win
outright and stops a shared expansion term from dominating.

**honcho v3.4.1 / v3.5.0** are, in a different register, the same
lesson. v3.4.1 fixes a filter bug in which a `"*"` wildcard or an
empty `{}` was silently *dropped* inside `AND`/`OR`/`NOT`, so a
query that was supposed to widen silently narrowed; and it stops
retrying a request the provider rejected outright, because three
attempts with eight seconds of backoff cannot fix a malformed
request. v3.5.0 adds the thing the release note calls out most
clearly: **explicit conclusions cite the messages they came from**,
persisted as edges so the citation survives the run.

The shared shape is: *a retrieval system that cannot be measured will
keep reporting numbers it does not deserve.* agentmemory fixed the
scorer and shipped a benchmark; honcho fixed a filter that quietly
dropped a term and made citations durable. Loop Memory had the same
disease in a form nobody had looked for: its lexical channel had
**never been measured**, and when the measurement was finally taken
it turned out that the published BM25 score was collapsing onto
SQLite's `1e-6` floor for ordinary CJK queries.

The rest of the window was consolidation hygiene. TencentDB made a
Redis outage degrade instead of block. Cognee made conflict resolution
durable and made permission failures loud. nanobot made conversation
history durable under the gateway's ownership while refusing to
restore a stale backup. OpenViking shipped a hotfix that turned a
feature *off* — automatic privacy discovery was replacing ordinary
content with placeholders — which is the same instinct as our
"dry run by default" dream pass, from the other direction.

## Adopted

**A1 — A retrieval-quality benchmark, and the defect it found.**
Loop Memory shipped hybrid retrieval in 0.3.x and never measured
whether the lexical channel ranked anything sensibly. The new
`loop-memory bench` scores the channel against a fixed, versioned
fixture (30 memories, 12 wiki pages, 11 judged queries) and reports
recall@1/3/5, MRR@10 and nDCG@10, together with the fixture's
revision and the SHA-256 of its bytes. The methodology is agentmemory's:
fixed corpus, content-addressed report, explicit limitations, no
provider API, $0 per run.

Building it is what found the defect. On the shipped fixture, the
pre-0.4.18 channel scored **MRR@10 = 0.6061, recall@1 = 0.2273,
nDCG@10 = 0.7078** — the right document was usually ranked *second*,
because SQLite's `bm25()` normalises by document length and the
verbatim answer was the longer note. The same fixture scores
**MRR@10 = 1.0000, recall@1 = 0.9545, nDCG@10 = 1.0000** after the
fix.

**A2 — The ranking fix (defect fix, not a feature).** SQLite's FTS5
`bm25()` computes the classic idf `log((N - n + 0.5) / (n + 0.5))`
and **clamps every non-positive idf to `1e-6`**. A query term present
in 49 % of the corpus keeps a real idf; one present in 51 % has its
weight annihilated. With the `trigram` tokenizer that is the *normal*
case for CJK — `知识图` occurs in more than half of any
knowledge-graph-heavy corpus — and the visible symptom was the 0.4.15
evidence chain reporting **`bm25: 0.0`**, i.e. "this hit because
bm25 0.0". The published channel score is now a textbook BM25
(k1 = 1.2, b = 0.75) with the Lucene / BM25+ idf
`log(1 + (N - n + 0.5) / (n + 0.5))`, which is strictly positive for
every term, so the scale cannot collapse and the ordering keeps a
meaningful discriminator.

**A3 — Exact matches first** (*agentmemory* v0.9.31). A document
that contains the query verbatim now outranks one that merely
contains the same scattered trigrams. This is the transferable part
of agentmemory's prefix-inflation fix, and it is what moved
recall@1 from 0.2273 to 0.9545 on the shipped fixture. The candidate
set is unchanged — the fix re-ranks, it does not add or drop
documents — and the `LIKE` fallback is now scored on the same scale
as the FTS5 hits instead of publishing the memory's `importance`
under the name `bm25`.

## Deferred

- **CJK word segmentation** — the trigram tokenizer finds
  *substrings*, not *words*, so a document that says "切分知识图谱的
  输入文档" is not retrievable by the query "知识图谱构建" even though
  a human would call it relevant. The fix in A2/A3 ranks the
  candidate set better; it does not widen it. Real segmentation needs
  a dictionary or a learned segmenter, which breaks the zero-dependency
  property. Defer to 0.5.0 as an optional extra.
- **honcho's durable conclusion→source edge table** (v3.5.0) — the
  *shape* is already ours: `wiki_pages.evidence_ids` stores the
  memory ids that contributed to a synthesised page, and 0.4.15's
  `evidence` array exposes the per-channel reason for every recall
  hit. What honcho adds is a first-class edge table with a DDL-only
  migration and no backfill. AGPL-3.0, so *pattern only, no code
  copied*. Not urgent: our provenance already survives.
- **honcho's LLM retry classification** (v3.4.1) — **already
  compliant, verified**: `loop_memory/llm/providers.py` raises
  `LLMHttpError` on the first failure and has no retry loop at all,
  so a malformed request is never re-sent three times.
- **honcho's wildcard/empty-filter semantics** (v3.4.1) — **not
  applicable, verified**: Loop Memory's filters are SQL built from
  parameterised predicates; there is no user-facing wildcard or
  empty-object filter grammar to drop.
- **honcho's CA-bundle refresh** (v3.4.1) — **not applicable,
  verified**: the project has no runtime dependencies and makes its
  outbound calls with the stdlib `urllib`, which uses the system
  trust store; the Docker image installs `ca-certificates` from the
  distribution's repository at build time. There is no `certifi`
  wheel to pin.
- **Cognee's durable conflict-resolution API** (v1.6.6) — our
  contradiction detector writes `contradicting_ids` and the
  supersession chain already answers "what did we believe last week?".
  A durable *user-facing* resolution endpoint is a product decision.
- **Cognee's fail-on-history-purge** (v1.6.6rc1) — our delete
  semantics are append-only (`cognitive_audit` records every action,
  nothing is destroyed), so there is no purge that can half-fail.
- **nanobot's gateway-owned durable conversation history** — our
  transcript ingest already writes into the same SQLite database the
  server reads, and `loop-memory snapshot` gives a portable copy.
- **OpenViking's Working Memory default OFF** (v0.5.2) — the same
  instinct already ships as the 0.4.16 dream pass (dry run by
  default, `apply` to commit). AGPL-3.0, pattern only.
- **TencentDB's Redis-interruption self-recovery** — Loop Memory has
  no Redis and no external service in the recall path; the closest
  analogue is the local SQLite store, whose `busy_timeout=5000`
  already absorbs a contended writer.
- **agentmemory's 500 ms optional-graph budget** — Loop Memory's
  graph channel (`adaptive=True`) is opt-in and off by default, so
  there is no slow optional stage in the default recall path to bound.
  Worth revisiting if the graph channel is ever promoted to default.
- **agentmemory's incremental summarisation** — our dream pass
  already only processes what changed.
- **openclaw/openclaw** — release notes show no substantive
  memory-surface change this window. Watchlist only.
- **mem0ai/mem0, letta-ai/letta, getzep/graphiti, langchain-ai/langmem**
  — no release inside the window. Standing watchlist.

## Rejected

- **OpenViking's automatic session privacy discovery** (v0.5.2,
  withdrawn by v0.5.2.1) — it replaced ordinary message content with
  privacy placeholders on false positives and wrote invalid privacy
  records. The upstream project disabled it within four days; we
  simply do not ship it.
- **Cognee's destructive consolidation** (`improve()` +
  `consolidate_entities` mutate or delete existing rows) — directly
  incompatible with our append-only audit guarantee.
- **Zep / Graphiti graph-native consolidation** — requires a graph
  database. Incompatible with our SQLite-first, zero-service
  deployment.
- **Copying honcho or OpenViking code** — both are AGPL-3.0. Every
  item above is *pattern only, no code copied*; the BM25 scorer in
  `loop_memory/storage/lexical.py` is a from-scratch implementation of
  the textbook Robertson/Sparck-Jones BM25 with the Lucene idf
  variant.
