## Headline

The window produced one theme that applies directly to Loop Memory's
logical-fact slots: **a slot has an identity, and it has a clock.**

* `TencentCloud/TencentDB-Agent-Memory` v2.0.4 (2026-11-19) shipped
  the clock half: "整理按对话发生的时间排序，后到的更早事实不再覆盖
  较新的结论" — organise by when the conversation happened, so a
  later-arriving *earlier* fact no longer overwrites a newer
  conclusion.
* `thedotmack/claude-mem` v15.19.0 (2026-11-16) shipped the identity
  half from the other direction: MCP `save_memory` now honours
  `CLAUDE_MEM_EXCLUDED_PROJECTS` (#6105) — "A save from an excluded
  checkout was stored over MCP while the same save over HTTP was
  skipped" — i.e. *two surfaces of the same operation must enforce
  the same rule*.
* `thedotmack/claude-mem` v16.0.0 (2026-11-18) removed a
  token-gated remote surface and made the worker **bind to loopback**
  when the token is missing, so "the full API is never open to the
  network without a token" (#6295).

Reading those against Loop Memory's own write path turned up four real
defects in `MemoryStore.upsert_memory`. The release that came out of
this audit is **0.4.23 — a fact slot has one namespace and one
clock** (`docs/namespace-isolation.md`).

## Decisions

### ADOPT — a fact slot has one namespace and one clock (shipped in 0.4.23)

**What.** Four defects in `MemoryStore.upsert_memory` and the HTTP
write surface:

1. **The write path could leave its namespace.** The namespace
   predicate was
   `((agent_id IS ? AND user_id IS ?) OR (agent_id IS NULL AND user_id IS NULL AND ? IS NULL))`
   — the second branch was gated on the *user_id* parameter, so any
   caller with an agent but no user also matched the **global** rows.
   An agent-scoped write therefore (a) **superseded a global row** of
   the same slot, so shared knowledge silently vanished from every
   other caller's recall, and (b) **collapsed onto a global row with
   the same text and overwrote it**, re-labelling shared knowledge
   with the agent's own `agent_id` — every other caller lost the
   memory. The namespace is now matched *exactly*, one
   `(agent_id, user_id)` pair, compared with the null-safe `IS`
   operator, so the global namespace `(NULL, NULL)` is a namespace
   like any other.
2. **The slot was ordered by arrival, not by fact time.** The
   supersession was "whatever was written last wins", so replaying an
   old transcript let a stale fact take the slot away from the
   current conclusion. The slot now keeps the version with the
   greatest **fact time** (`COALESCE(valid_at, created_at)`); a
   late-arriving older fact is recorded as the historical version
   instead of replacing what we already know.
3. **`POST /api/v1/memories` validated `created_at` and then dropped
   it**, stamping the row with "now" — which is what made a fact's
   fact time indistinguishable from its arrival time. The batch route
   and the SDK already honoured it; the single-item route now matches
   them, and the batch route gained `subject_key` so a slot can be
   written in bulk.
4. **A global `external_id` re-push created a duplicate row.** The
   unique index `(agent_id, user_id, external_id)` cannot catch it —
   SQLite treats NULLs as distinct inside a unique index — and the
   re-route was guarded by `agent_id is not None`.

**Why.** `TencentDB-Agent-Memory` v2.0.4 shipped the clock half in
one line: "整理按对话发生的时间排序，后到的更早事实不再覆盖较新的
结论". `claude-mem` v15.19.0 shipped the identity half from the other
direction: the MCP `save_memory` tool stored a save that the HTTP
route had skipped (#6105) — *the same operation must enforce the same
rule on every surface*, which is exactly the shape of defect (3) here
(the single route and the batch route disagreed about `created_at`).
`honcho` v3.6.0 and `EverOS` v1.6.0 (last cycle) had already made
every read *and write* tenant-scoped; the write side of Loop
Memory's own namespace model was the half that had been left open.

Full contract: `docs/namespace-isolation.md`.
22 new regression cases (9 of them fail against 0.4.22); suite at
**1106 passed / 4 skipped**.

### DEFER — the consent list (EverOS v1.7.1)

> "a speaker with `consented: false` is not written at all (one
> decline in a batch drops all of that slot's lines)"

A per-subject opt-out that applies to the *whole batch*: one decline
drops every line of that slot. Loop Memory has no consent concept at
all — every write is accepted and only `delete_memory` can undo it.

**Why deferred.** It needs a policy store (who consented to what, and
when), a rule for what happens to rows that were written before a
decline, and a decision on whether a decline is per-agent,
per-user or per-slot. That is a product decision, not a bug fix, and
it deserves its own release rather than being bolted onto a
correctness one.

### DEFER — offline summary writing (EverOS v1.7.1)

> "Every copy is stored with a placeholder summary: the episode's
> opening, cut at a word boundary to a width of 120 … `summarize_episode`
> then writes the model's preview from the stored episode text, and
> replaces only the copies still showing the placeholder, so a summary
> edited in the meantime is kept."

The write never blocks on the model call; the expensive part happens
later and is idempotent, and a human edit is never clobbered.

**Why deferred.** Loop Memory's ingest pipeline already writes without
a model call and lets the consolidator / dream pass fill the wiki in
later — the shape is the same. What is missing is the
compare-and-set ("replace only the copies still showing the
placeholder"), which is a small but real addition to the
consolidator's write path. Worth its own release, once the
consolidator's idempotency story is written down.

### DEFER — the pending list (EverOS v1.7.0, carried over)

> "information seen only once waits here until a later conversation
> confirms it, which cuts down on wrong entries"

Still deferred from last cycle, for the same reason: Loop Memory has
`importance`, `valid_at` / `invalid_at` and the supersession chain,
but not the *observation count* that would drive the gate.

### REJECT — the loopback bind (claude-mem #6295)

claude-mem now binds a worker to `127.0.0.1` and logs a `SECURITY`
error when it finds a token-gated surface but no token.

**Why rejected.** Loop Memory already refuses to do the equivalent
thing, and refuses it *earlier*: `loop-memory serve` binds to
`127.0.0.1` by default (0.4.21), the remote SDK refuses to send
memory data over a plaintext connection, and `doctor` reports
`plaintext_exposure` on every run. Adding a second, token-shaped
mechanism would duplicate an existing guarantee with a weaker one.

### REJECT — the bounded export (openclaw v2026.10.33)

> "Long conversations and large session stores use bounded export and
> recovery work, reducing out-of-memory failures during chat, memory
> export, Doctor repair, and Gateway startup."

**Why rejected (for now).** Loop Memory's export and doctor already
page through the store rather than loading it whole, and the
`audit_log` growth that `doctor` warns about is a known, reported
condition rather than a crash. Bounding the work further is a
performance change with no correctness defect behind it — it deserves
a measurement, not a guess.
