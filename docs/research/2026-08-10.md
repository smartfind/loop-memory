### 1. TenCentDB Agent Memory v2.0.0 (2026-08-03) — surveillance-only

- **Source.** Release `TencentCloud/tencentdb-agent-memory v2.0.0`
  on 2026-08-03. Public tag + release notes. Repo default branch is
  `feat/server_team`. Closed issues batch on 2026-08-10 covers
  v2.0.0 followups.
- **License.** Apache-2.0.
- **Decision.** `defer`. Still on the watchlist but **not** being
  adopted. Local-first / single-user / MIT-only / no proxy-required
  posture is the non-negotiable that TencentDB's multi-tenant,
  Memory-Proxy MITM architecture explicitly rejects. Track quarterly
  — see `docs/research/2026-08-01.md` §1 for the four-asset model
  (Chat Memory / Skill / Wiki / CodeGraph) and the watchlist entry
  in `scripts/weekly_research_update.sh`.
- **Notable v2.0.0 bug worth holding up as a mirror image of our
  design.** Issue **"L0 embedding timeout silently degrades to
  metadata-only write with code:0 — MAX_RETRIES=0 leaves retry
  scaffold disabled"** (2026-08-10). The user-visible smoke test
  shows `code:0` (success) while the write actually dropped to a
  metadata-only degraded state. This is exactly the silence-vs-no
  failure pattern Loop Memory's smoke pipeline (see
  `scripts/weekly_research_update.sh` and the install smoke suite
  under `/tmp/lm-install-tests/smoke.sh`) is built to forbid — every
  probed code path must exit 0 **and** actually do the work, and
  the regression test `test_every_registered_subcommand_has_help_text`
  in `tests/test_cli_version.py` exists to make the exit-code
  contract un-gameable.

### 2. Cognee v1.4.2 — "Search & Reliability Improvements" (2026-08-08)

- **Source.** Release `topoteretes/cognee v1.4.2` on 2026-08-08,
  plus commit log for the surrounding week.
- **License.** Apache-2.0.
- **Highlights.**
  - `fix: Avoid nested DB sessions that deadlock the pool (#4389)`
  - `fix: Release DB connection before nested acquisitions (#4392)`
  - `perf: Keep idle subprocess engines alive for a TTL (#4384)`
  - `refactor: Deduplicate engine cache ops (#4387)`
  - `fix(graph): Preserve inherited fields in extraction schemas (#4373)`
  - `fix: invalidate pg session on request cancellation (#4250)` (2026-07-31)
  - SDK groundwork: `DEFAULT_DATASET_NAME constant + as_uuid/warn_once
    helpers (#4284)`.
- **License / applicability.** Apache-2.0, but Cognee is a
  knowledge-graph ingestion framework, not an agent memory store —
  overlap with Loop Memory is the LLM-driven extraction pass +
  typed-graph story, not the recurring-lifecycle / session-watcher
  story. None of the eight PRs above maps cleanly to a bug class
  Loop Memory currently has.
- **Decision.** `defer`. No liftable pattern this week. The nested-
  session / connection-pool deadlock pair is a useful reminder that
  SQLite's single-writer connection regime (which Loop Memory relies
  on via `loop_memory/storage/sqlite_store.py`) is a forcing function
  that prevents this entire class of bug — keep that posture.

### 3. Mem0 — vector-store filter validator batch (2026-08-09 ~ 2026-08-10)

- **Source.** 8-10 PR batch from `mem0ai/mem0`: `pgvector`,
  `s3vectors`, `turbopuffer`, `weaviate`, `cassandra`,
  `ts-oss/upstash`. Common shape: validate filter values / keys
  before passing to the store, raise `ValueError` on bad shape.
- **License.** Apache-2.0.
- **Pattern.** When filter values weren't a list / didn't match the
  expected scalar shape, Mem0 was silently dropping the filter
  (Upstash) or returning wrong results (Cassandra) instead of
  raising. The fix is a validator per backend, not a single
  centralised path — because each backend has its own filter
  grammar.
- **Applicability to Loop Memory.** Loop Memory's
  `loop_memory/jobs/contradiction.py`, `loop_memory/export/`, and
  `loop_memory/serve/handlers.py` issue SQL through
  `loop_memory/storage/sqlite_store.py` with parameterised queries
  (no string interpolation of user input). The validator-before-
  fire pattern Mem0 is retrofitting is already enforced here by
  `sqlite3`'s "only one statement per `execute()`" rule plus the
  parameterised form. No silent-drop bug class exists; the SQL
  surface is intentionally narrow.
- **Decision.** `defer`. No retrofit required. File under "watch
  the same anti-pattern if we ever add a non-SQLite vector store
  via the `[chroma]` extra".

### 4. Mem0 — "fix(memory): prevent cross-scope entity merges" (PR open 2026-08-10)

- **Source.** `mem0ai/mem0` PR opened 2026-08-10 by external
  contributor `wangjiawei-vegetable`.
- **License.** Apache-2.0.
- **Pattern.** Without the fix, a write to `user_id=A` could merge
  entities into a graph row that already existed for
  `user_id=B` if the entity text matched. The fix scopes the merge
  candidate lookup by `user_id`/`agent_id`/`run_id`.
- **Applicability to Loop Memory.** Loop Memory's
  `loop_memory/graph/extract.py` and `loop_memory/graph/build.py`
  keep a single SQLite table for entities and a separate
  `entity_mentions` table for the (memory_id, entity_id, source,
  scope) tuple. The merge is already scoped by `source` (the
  ingest source name) and the explicit `scope` field on the wiki
  page (`scope="global"` vs `scope="codex"` etc., see
  `tests/test_wiki_classifier.py` and `loop_memory/wiki/scope.py`).
  The cross-scope merge bug class is unreachable as long as the
  `entity_mentions` scope column stays non-null.
- **Decision.** `defer` (with a regression guard). Loop Memory's
  schema is intentionally different from Mem0's here on purpose:
  - `entities` table: one row per `name` (no `source` column).
  - `entity_mentions` table: `(memory_id, entity_id)` unique pair,
    no `source` column.
  The missing `source` column is by design — a "Codex" entity is the
  same Codex regardless of which agent mentioned it, and the
  cross-source co-mention is a **feature** (boosts recall when one
  source asks about something the other source already mentioned).
  This is different from Mem0's multi-tenant model where two
  `user_id` values must never merge into the same entity row.
  A regression test in `tests/test_graph.py` pins the intentional
  shape: two memories from different `source` values that mention
  the same entity produce **one** `entities` row and **two**
  `entity_mentions` rows, and recall still returns both memories.

### 5. Mem0 — Upstash filter operators dropped silently (2026-08-10)

- **Source.** `mem0ai/mem0` issue + PR by `ac12644` on 2026-08-10 —
  the `ts-oss/upstash` backend was translating the
  `in` / `nin` / `*` filter operators into an empty filter, so
  `search()` returned nothing and `getAll()` returned nothing.
- **License.** Apache-2.0.
- **Pattern.** Silently dropping a non-empty filter to an empty
  filter looks like a "no results" outcome to the caller — they
  have no way to know the filter was discarded.
- **Applicability to Loop Memory.** Loop Memory's storage stack is
  SQLite + an in-memory cosine ranker (`loop_memory/backends/`),
  with an optional `[chroma]` extra. No opaque filter-translation
  layer exists; every retrieval is a single SQL `SELECT` with a
  `WHERE` clause we own. The `[chroma]` extra path goes through
  `loop_memory/backends/vector_store.py`'s `VectorStore` protocol
  and does not currently translate filter syntax — call sites pass
  Python-side scorers directly.
- **Decision.** `reject`. No fix required.
