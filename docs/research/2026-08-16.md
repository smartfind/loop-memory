## Window summary

The seven-week window saw **Mem0 ship v2.0.18** with a small but
high-quality batch of defensive-validation fixes (see §1), and **Cognee
ship v1.5.0** on 2026-08-15 — the first major version bump since the
prior cycle, landing large-scale migration tooling, a new
``LLM_TEMPERATURE`` / ``LLM_SEED`` env-var pair, and a community-plugin
guide. **TencentDB Agent Memory** published **v2.0.1-beta.2** on
2026-08-15 with notable Memory-Proxy client additions (Codex CLI,
WorkBuddy, DeepSeek Harness dsh) and per-page wiki retry/recovery —
still on the watchlist, still not adopted. **Letta** continues the
0.16.8 freeze (now 13+ weeks) at v0.16.8.

Three new Apache-2.0 projects crossed into the radar this cycle and
are flagged for ongoing observation but **not adopted** today:

- **EverOS** (`EverMind-AI/EverOS`, 12k stars). Apache-2.0.
  Self-described as "local-first, Markdown-native, user-owned,
  self-evolving". Topic tags include ``clawdbot-skill`` (direct
  positional overlap with us), ``agent-memory``, ``long-term-memory``,
  ``mcp``. The architectural surface area is close enough that
  porting its "fails loudly instead of quietly" pattern (§5) is
  the kind of small, high-confidence lift that survives an

- **MemOS** (`MemTensor/MemOS`, 10k stars). Apache-2.0. Topic tags
  include ``openclaw``, ``hermes``, ``claude``, ``chatgpt`` —

  Hermes Windows-path fixes, ``cachetools`` promoted to a core
  dependency, and ``UniversalAPIEmbedder`` ``embedding_dims``

  embedding pipeline.

## Material findings

### 1. Mem0 v2.0.18 — defensive validation batch (2026-08-11)

- **Source.** Release `mem0ai/mem0 v2.0.18` on 2026-08-11.
- **License.** Apache-2.0.
- **Highlights.**
  - **PR #6892** — percent-escape ``%``, ``&``, ``=`` in
    ``user_id``, ``agent_id``, ``run_id`` when building the
    session-scope key for the recent-conversation buffer. The key
    now stays unambiguous for ids that contain separator chars;
    ordinary ids map to the same key, only id values containing
    the special chars route to a new key.
  - **PR #6879** — raise ``ValueError`` when a PGVector ``in`` /
    ``nin`` filter value is not a list. Previously a string value
    was iterated character-by-character into ``= ANY(...)``, so
    ``{"user_id": {"in": "alice"}}`` matched ``a``, ``l``, ``i``,
    ``c``, ``e`` — a **silent partial-match** data corruption.
  - **PR #6848** — reject ``index_accuracy=0`` in the Oracle AI
    Vector Search config. The range check sat behind a truthiness
    test, so ``0`` skipped validation entirely and was passed
    through to ``WITH TARGET ACCURACY 0``.
  - **PR #6839** — close the Oracle connection or pool that Mem0
    opened when initialization fails (version check, ``create_col``
    error). Previously the connection leaked for the life of the
    process.
- **Decision.** `defer` (with a regression guard added this cycle
  — see §4 below). The four PRs share one underlying shape:
  **silent partial-match / silent zero acceptance** — a caller
  passes a "looks plausible" value, the layer quietly coerces it,
  and the user sees a degraded outcome with no error. Mem0's
  defensive-validation discipline is the right default. Loop
  Memory's parameterised-SQL surface already enforces it for
  queries, but the truthiness-vs-``is not None`` class of bug
  surfaced during this cycle's audit of our own cognitive_sleep
  deadline code (§4), so the lesson is now pinned by tests.

### 2. Cognee v1.5.0 — large-scale migration & graph reliability (2026-08-15)

- **Source.** Release `topoteretes/cognee v1.5.0` on 2026-08-15,
  drawing on PRs #4477, #4504, #4505.
- **License.** Apache-2.0.
- **Highlights.**
  - **Large-scale migration release-test CI** — production-shaped
    two-dataset fork split + rekey validation runs on every
    release.
  - **Ladybug (graph adapter) stability** — set-based fork re-key,
    chunked queries, batched rekey/restore.
  - **Community-plugin guide** + Letta/MemGPT/Zep migration tutorial.
  - **``LLM_TEMPERATURE`` env-var plumb** + **``LLM_SEED`` support**
    for reproducible outputs when the provider supports seeds.
  - Windows TLS fix (ship OpenSSL with the wheel) + batched OTLP
    log export.
- **Adoption this cycle.** **LLM_TEMPERATURE + LLM_SEED env-var
  plumb is adopted.** See `loop_memory/llm/providers.py` and
  `loop_memory/llm/openai_adapter.py` — both env vars are read at
  every ``complete()`` call in the OpenAI-compat / Anthropic /
  Ollama providers, with explicit ``kwargs`` still winning so every
  existing call site is unchanged. Pinned by 11 new cases in
  `tests/test_llm_providers.py::LLMEnvVarTests`.
- **Why this one and not the rest.** The migration-test CI,
  Ladybug re-key work, and Windows TLS work all target a
  production-graph stack we don't have — Loop Memory's SQLite-only
  posture avoids the relevant bug classes. The env-var plumb is
  small, isolated, and gives the user a deterministic-distillation
  escape hatch without touching the behaviour config.

### 3. TencentDB Agent Memory v2.0.1-beta.2 (2026-08-15) — surveillance-only

- **Source.** Release `TencentCloud/tencentdb-agent-memory v2.0.1-beta.2`
  on 2026-08-15.
- **License.** Apache-2.0.
- **Decision.** `defer`. Still on the watchlist but **not** being
  adopted. Local-first / single-user / MIT-only / no proxy-required
  posture is the non-negotiable that TencentDB's multi-tenant,
  Memory-Proxy MITM architecture explicitly rejects. Track
  quarterly — see `docs/research/2026-08-01.md` §1 for the
  four-asset model (Chat Memory / Skill / Wiki / CodeGraph) and
  the watchlist entry in `scripts/weekly_research_update.sh`.
- **What is new this cycle and worth noting.** (i) Memory-Proxy
  now lists **Codex CLI**, **WorkBuddy**, and **DeepSeek Harness
  (dsh)** as first-class clients — the Memory-Proxy architecture
  is actively widening the agent-ecosystem surface it can MITM.
  (ii) Wiki generation moved to **parallel page construction with
  per-page auto-retry and real-time progress** — a real
  observability lift on a batch pipeline. (iii) Skill extraction
  coverage widened, and private Skill retrieval is now indexed.
  The per-page auto-retry pattern (one page failure no longer
  stalls the whole batch) is the same shape as the EverOS
  "fails loudly instead of quietly" theme in §5 — and is a
  small, viable pattern to lift when Loop Memory grows a wiki
  batch endpoint.

### 4. Loop Memory audit — defensive-validation round (this cycle)

- **Trigger.** While reviewing Mem0 v2.0.18 §1, we audited the
  Loop Memory surface for the same silent-partial-match bug class
  (truthiness where ``is not None`` was meant).
- **Found.** `loop_memory/jobs/cognitive.py::cognitive_sleep`
  was reading
  ``deadline_at = (now + float(deadline_seconds)) if deadline_seconds else None``
  — which silently downgrades ``deadline_seconds=0.0`` to
  ``deadline_at=None``. A caller passing ``0.0`` to mean
  "fail-fast / never run" would otherwise get a sweep that ran
  to completion. Identical shape to Mem0's Oracle
  ``index_accuracy=0`` (PR #6848).
- **Fix.** Explicit ``is not None`` check. Pinned by
  `tests/test_universal_memory.py::CognitiveSleepObservabilityTests::test_deadline_aborts_with_stage_named`
  and the route-level
  `test_route_honours_explicit_deadline_seconds_zero`. The HTTP
  route now also threads ``deadline_seconds`` through
  `POST /api/v1/cognitive/sleep`.
- **Pattern adopted this cycle (Cognitive sleep observability).**
  Per-stage timings on ``CognitiveReport.stages``, an optional
  ``progress: Callable[[str], None]`` callback so the UI can
  render a live stage progress bar, and a ``deadline_seconds``
  budget that fires ``aborted=True`` with an ``abort_reason``
  that **names the stage** the budget fired in. Mirrors the
  EverOS "stalls must name the table / phase" convention in §5.
- **Pattern adopted this cycle (Cognitive sleep N+1 SQL).**
  The stale + low-value gates share one pass over the row set;
  signals are bulk-fetched in a single ``IN (?, ?, …)`` query
  via the new ``MemoryStore.get_signals(memory_ids)`` method
  instead of one ``get_signal`` round-trip per row. Net result
  for a sweep at ``limit=1000``: roughly **1000 SQL round-trips
  → 1**. Pinned by 4 new cases in
  `tests/test_universal_memory.py::GetSignalsBulkTests`.

### 5. EverOS v1.2.3 — "fails loudly instead of quietly" (2026-08-07)

- **Source.** Release `EverMind-AI/EverOS v1.2.3` on 2026-08-07.
- **License.** Apache-2.0.
- **Highlights.**
  - A 100-minute table that stopped reclaiming disk while
    ``/health`` stayed green led to a six-place audit that
    hardened every "stuck-but-silent" path: reads with no
    deadline now have one, background loops die loudly, alert
    counters aren't reset by the remediation they trigger.
  - Agent skill extraction rescued from a retry-then-dead-letter
    loop by carrying target-case data on ``SkillClusterUpdated``
    and reading existing skills from markdown for strong
    consistency.
  - ``POST /api/v2/ome/trigger`` now distinguishes
    ``not_dispatched`` (gates rejected — usually missing
    ``"force": true``) from ``ok`` (dispatched + settled),
    surfacing dead-lettered strategy runs in a new ``runs``
    field.
  - OME strategy retries now back off
    ``min(base * 2**(attempt-1), cap)`` plus up to jitter, so
    retry-class errors no longer exhaust their budget in
    milliseconds.
- **Decision.** `defer` (continue watching). The architecture
  overlaps with ours, but the per-page retry-and-surface pattern
  is **already adopted by us** in this cycle via the
  cognitive_sleep deadline + per-stage ``abort_reason`` shape in
  §4. The remaining EverOS work targets a hosted / proxy setup
  we don't have.
