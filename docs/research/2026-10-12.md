## Window summary

The 2026-10-05 → 2026-10-11 window is quieter than the previous two
but produces two notable themes:

1. **OpenViking Gateway (AGPLv3, 2026-10-09)** is the biggest
   single design move of the window. OpenViking ships a separate
   `openviking-gateway` process that sits between any model client
   and the model API; the client changes two values (base URL +
   API key) and the gateway transparently injects OpenViking
   memory into every turn. Memory is replayed byte-for-byte on
   subsequent turns so the provider's prompt cache and Claude
   thinking signatures stay valid. The gateway supports
   Anthropic Messages, OpenAI Chat Completions, and OpenAI
   Responses — no protocol translation. v0.5.0 also flips
   Working Memory to default-off across plugins (Claude Code,
   Codex, OpenCode, pi, OpenClaw), pushing the host harness to
   own history + compression. The MITM-gateway pattern is
   interesting but **incompatible** with our local-first single-
   user MIT design (a network-level proxy would break "the
   process owning the data is the process owning the
   conversation"); the per-harness Working-Memory flip is
   semantically what we already do (Loop Memory is *only* an
   external memory surface — history stays with the host).

2. **Auto-diagnostic / "doctor" commands** are becoming a
   standard feature in the agent-memory stack:
   `cortexkit/magic-context` ships `npx @cortexkit/magic-context
   doctor` to auto-detect harness conflicts, verify plugin
   registration, check database integrity, and fix what it can.
   `PerryLink/dsh-memento` ships a `dsh-plugin-doctor` CI badge
   for the DSH ecosystem. The pattern is small (one CLI command
   + a small checklist of common-store problems + a severity
   field) and high-value (a user who runs `doctor` and sees 0
   problems knows their store is healthy; a user who runs it
   after a migration sees exactly what broke). Implication for
   Loop Memory: we already have `/api/healthz` + `/api/readyz`
   for the *server* but no command for the *store*. `loop-memory
   doctor` would complement those probes with a client-side
   report (audit-trigger coverage, schema version, wiki/memory
   /relation integrity, hook installation, scope leaks).

3. **Hindsight v0.10.3 (2026-10-08)** is a quiet bug-fix
   release. The interesting change is "treat memory as a past
   record, and let teams add their own guidance" — they're
   adding a non-memory guidance channel so the *system prompt*
   and the *retrieved memories* don't get conflated. Loop
   Memory already separates these (the wiki is guidance; the
   memory table is past records) so this is a non-event for us
   but worth noting for the Watchlist.

4. **Cognee v1.6.3 (2026-10-07)** tightens temporal-search
   windows, removes the `temporal_cognify` config option, and
   pins DLT below 1.31 to avoid an upstream import regression.
   We don't use DLT; no liftable pattern.

5. **TencentDB Agent Memory v2.0.2 (2026-10-09)** closes the
   v2.0.2 beta line. The four-asset model (Chat Memory / Skill /
   Wiki / CodeGraph) is unchanged. **Still watchlist-only** per
   the 2026-09-13 + 2026-09-20 + 2026-09-27 + 2026-10-05 cycles.

## Adopt / defer / reject

### Adopted this cycle → `0.4.14`

- **`loop-memory doctor` auto-diagnostic command** (audit
  2026-10-12). One CLI subcommand + a small library of
  checkers that each report `(name, status, severity,
  message, fix_hint)`. Severity is one of `ok` / `info` /
  `warn` / `error`. `--fix` applies the auto-repair for any
  check that has one; the rest are reported as
  human-action-required. Default exit code is 0 when no
  `error` checks fire, 1 when at least one `error` check
  fires. Output is human-readable by default and JSON with
  `--json` for scripting. Source attribution:
  `cortexkit/magic-context` `npx @cortexkit/magic-context
  doctor` (MIT, 2026-10-12) + `PerryLink/dsh-memento`
  `dsh-plugin-doctor` (Apache-2.0, 2026-10-12). The *pattern*
  is not copyrightable; only the code is, and we re-implement
  from scratch against our own `MemoryStore` API.

  **Initial check list** (each is its own function, easy to
  add more over time):
  - `db_exists` — the SQLite file is present + readable.
  - `db_integrity` — `PRAGMA integrity_check` returns `ok`.
  - `schema_version` — `schema_meta.value` matches
    `SCHEMA_VERSION` from the installed wheel.
  - `audit_triggers` — the 12 SQLite triggers from 0.4.12
    are installed on `memories` / `wiki_pages` / `relations`
    / `consolidation_runs`.
  - `audit_log_writable` — a probe INSERT into `audit_log`
    succeeds (writes are inside `_conn` so they show up under
    the Python wrapper or the DB trigger).
  - `audit_log_size` — the `audit_log` table isn't unusually
    large vs. the `memories` + `wiki_pages` rows (heuristic
    `>= 100x` triggers a `warn` so the user can prune).
  - `hooks_installed` — at least one known agent
    (codex/claude/hermes/openclaw) is registered in
    `agents` with `hooks_installed=1`.
  - `version_consistent` — the running `loop_memory
    __version__` matches the package metadata (`importlib
    .metadata.version`).
  - `wiki_no_orphans` — every `wiki_pages.scope, slug` row
    that other rows reference still exists (defensive: catches
    a stray FK-less relationship table inconsistency).
  - `recall_paths_works` — calling `recall_paths` against a
    known seed query returns the expected shape.

### Deferred

  network-proxy model breaks local-first single-user).
- **OpenViking's "Working Memory default-off" flip** — already
  what Loop Memory does (we *only* store memory; history is
  the host's). No code change needed; add a one-line note to
  the README "Why Loop Memory" section next cycle.
- **Hindsight v0.10.3 "memory-as-past-record" separation** —
  already the loop-memory model. Non-event.

  defer as 0.4.13.

  shadows the venv's site-packages; macOS `/tmp` resolves to
  `/private/var/folders/...` (0.4.10 path-safety helper
  allow-lists `/var/folders/`, `/var/tmp/`, `/tmp/`,
  `/private/tmp/`, `/private/var/folders/`).
