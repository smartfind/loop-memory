## Window summary

The 2026-10-13 → 2026-10-25 window is the busiest consolidation cycle
the ecosystem has produced. Three themes converge, and together they
describe almost exactly the shape of what Loop Memory shipped this
week:

1. **Consolidation moved off the request path and became a first-class
   *lifecycle state*.** Mem0's *Dream* splits maintenance into merge,
   supersede and synthesize, runs merge/supersede at write time but
   synthesis **on a schedule off the request path** (weekly on Pro,
   daily on Enterprise), and stores the lifecycle state **as an indexed
   column** on every memory. Databricks' *MemCurrent* (2026-10-20)
   makes the same split with numbers attached: its offline "dreaming"
   pipeline scores **63.5 %** where its online tool-calling memory
   scores **53.9 %**, and the full system reaches **68.4 %** task
   completion (vs. **22.3 %** with no memory) while using **31 % fewer
   tokens** (≈1.44× cheaper) and running **26 % faster**. Anthropic's
   managed-store *Dreams* preview does the same thing as a
   background pass over an already-live store. The shared lesson:
   *the write path stays cheap and the read path stays simple; a
   separate, scheduled job reconciles the store.*

2. **"Latest only" became a first-class read flag — and it changed the
   default.** Mem0 v2 ships `latest_only` on `search` and `get_all`,
   plus `include_merged` to reveal merged duplicates; superseded
   memories are *hidden by default* and remain retrievable only when
   explicitly asked for. A cross-vendor comparison puts the principle
   crisply: *"the version you get is decided by whoever is reading,
   every time, not once by the store."* Loop Memory was on the
   **other** side of that default: our hybrid recall returned *both*
   versions of a superseded fact. That was not a design choice we had
   made — it was an oversight in the BM25 / LIKE / semantic channels,
   and it is fixed this cycle.

3. **Deletion gave way to pointer-based supersession.** Mem0's Dream
   states the rule outright — *"Nothing is deleted… pointer to the
   newer memory"* — and Mem0's expiration *"hides a memory, it does not
   delete it."* Primnox keeps successor links for replaced facts and
   retires them at query time. arXiv 2605.27366 (*In Defense of
   Forgotten*) makes the eviction side concrete: TTL-aware,
   **utility-weighted** forgetting beats pure recency, because a
   frequently-recalled old fact is worth more than a never-used
   fresh one.

A fourth, quieter thread is **hardening**: `agentmemory` v0.9.30
flips auth on by default, adds a durable capture inbox with retries
and dead letters, and confines import/export paths. Not a memory
*model* change, but it confirms the direction of travel for
single-user local memory servers.

## Adopt / defer / reject

### Adopted this cycle → `0.4.16`

**A1 — Subject-key logical fact slots with pointer-based supersession**
(*Mem0 Dream* supersede + *Primnox* successor links). A new nullable
`subject_key` column names the *logical slot* a fact occupies
(`"editor.preference"`). Two memories sharing
`(subject_key, agent_id, user_id)` are two **versions** of one fact.
`upsert_memory(subject_key=...)` makes the new row live and
soft-supersedes the previous one with a `superseded_by` pointer —
nothing is deleted, so `recall_as_of()` still answers *"what did we
believe last week?"*. `SCHEMA_VERSION` 12 → 13 with an idempotent
in-place `ALTER TABLE`. Content-hash dedup became slot-aware, so two
*different* slots holding the same text stay two rows.

**A2 — `latest_only` recall** (*Mem0 v2* `SearchMemoryOptions.latest_only`
parity). `recall()` and `recall_hybrid()` gained `latest_only=False`
(default unchanged, so the 0.4.15 contract holds). When enabled it
collapses in three layers: (1) drop rows whose validity window does
not contain *now*; (2) resolve each subject-key slot to its newest
**live** row — looked up *in the store*, so a stale version cannot win
merely by matching the query better; (3) cluster near-duplicate texts
by token Jaccard (default `0.85`), newest wins.

**A3 — The dream pass** (*Mem0 Dream* synthesis + *MemCurrent* offline
dreaming + *Anthropic Dreams*). New `loop_memory/jobs/dream.py`:
deterministic, zero-dependency, **non-destructive**, and **off the
request path** — exactly the split the ecosystem converged on. Three
stages: decay (rescore) → utility-aware soft expiry → near-duplicate
merge. Utility is `0.45 × importance + 0.30 × usage + 0.25 × recency`
(usage saturates at 10 recalls). Soft expiry stamps `invalid_at`;
it never deletes. **Dry run by default** (`--apply` to commit), and
every decision lands in `cognitive_audit` so it can be shown and
reverted. Exposed as `loop-memory dream` and `POST /api/v1/dream`.

**A4 — TTL / utility-aware expiry primitives** (arXiv 2605.27366 +
*agentmemory* forgetting curve). New `MemoryStore.expire_memory()` and
`revive_memory()`; `memory_stats()` now reports `subject_key`, `ttl`,
`valid_at`, `invalid_at` and a derived `ttl_state`
(`active` / `expiring` / `ttl` / `expired` / `persistent`).

**A5 — Bug fix: the hybrid path stopped returning superseded rows.**
This is the one item where the research turned into a *defect fix*
rather than a feature. The BM25 channel, the `_like_fallback` (both
whole-string and per-token SQL) and `search_by_embedding` all failed
to exclude `superseded_by IS NOT NULL` rows, so `recall_hybrid()` —
the production path behind the CLI, the MCP server and the dashboard —
returned **both** versions of a superseded fact. Mem0 removed
superseded memories from its search indexes; we now do the same.

**A6 — Lifecycle state as an indexed column** (*Mem0 Dream*). Our
`invalid_at` + partial index on `subject_key` give the same
property: the "is this still current?" question is a cheap indexed
lookup rather than a scan-and-compare at read time.

### Deferred

- **MemCurrent's episodic + derived two-layer with an LLM-generated
  `memory.md` index** — the strongest *measured* result in the window
  (68.4 % vs. 22.3 %, 31 % fewer tokens), but the derived layer is
  produced by an LLM. Loop Memory ships **no LLM dependency** and must
  stay that way for a local-first single-user install. Defer the
  *two-layer shape* to 0.5.0; the deterministic part (merge + expiry)
  already landed as A3/A4.
- **Anthropic *Dreams*** — scoped to Anthropic's managed memory
  stores. Not liftable, but its "reorganised store, live store
  untouched" property is exactly what A1+A3 implement.
- **Primnox query-dependent retirement** — retiring a fact when the
  *query* makes it redundant needs query-dependency tracking we do
  not record. Defer to 0.5.0 alongside the outcome-weighted utility
  item.
- **Outcome-weighted utility** — a cross-vendor comparison notes that
  almost no engine "ties ranking to a recall's outcome"; our utility
  score uses importance/usage/recency because we have no outcome
  feedback channel. Adding one is a product decision, not a weekly
  one.
- **TencentDB L0–L3 layers + JiuwenMemory L0/L1 tiered index with
  RRF / CombMAX fusion** — a bigger surface than a weekly cycle; our
  hybrid channel already fuses BM25 + LIKE + semantic, and the
  *tiering* (hot/cold split with its own indexes) is a 0.5.0 item.
- **Graphiti / Zep bi-temporal edge history** — we already expose
  validity windows and `as_of_ts` from 0.4.15; edge-level bi-temporal
  versioning is a schema-sized change. Defer.
- **Letta memory-block last-write-wins vs. MemFS git-backed
  versioning** — git-backing the *store itself* is a packaging
  decision (`.git` per DB, backup semantics, secret hygiene). Defer
  to 0.5.0.
- **agentmemory v0.9.30 auth-on-by-default + durable capture inbox** —
  the capture-inbox / retry / dead-letter design is a good fit for
  our `cognitive_audit` write path, but hardening the *server* is a
  separate workstream from the memory model. Carry as a watchlist
  item for the 0.4.x hardening series.
- **openclaw/openclaw v2026.10.7** — release notes show no
  memory-surface change this window. Watchlist only.
- **caviraoss/openmemory** — the repo now answers `301 Moved
  Permanently`; the watchlist entry needs a re-point before the next
  cycle.
- **Funes v1.9.1 (HuggingFace, Rust)** — the HuggingFace API did not
  answer this cycle, so the entry could not be re-verified. Stays on
  the watchlist unreviewed.
- **JiuwenMemory v0.2.0** — Huawei openEuler project, not on GitHub;
  the L0/L1 + RRF/CombMAX shape overlaps our existing hybrid fusion.

### Rejected

- **Cognee's destructive consolidation** (`improve()` +
  `consolidate_entities` mutate or delete existing rows) — directly
  incompatible with our append-only audit guarantee
  (`cognitive_audit` records every decision; nothing is destroyed).
- **Zep / Graphiti graph-native consolidation** — requires a graph
  database. Incompatible with our SQLite-first, zero-service
  deployment.
- **MemCurrent's hosted "consolidation off by default" posture** — not
  applicable to a self-hosted store; our dream pass is opt-in *and*
  dry-run by default, which is the stronger guarantee.

  <loop-memory@users.noreply.github.com>` only; no `Co-authored-by`
  trailers. Every behaviour change ships with a regression test — **77
  new cases this cycle** across four new files (see CHANGELOG.md).
- **Security posture unchanged.** The dream pass is read-only by
  default and cannot delete a row; `expire_memory()` only stamps
  `invalid_at`. The `superseded_by` pointer keeps the superseded row
  fully readable, so a bad consolidation can be undone by
  `revive_memory()` or by an explicit audit-log review.
- **Sandbox carry-overs (unbreakable).** `cwd` does not persist
  between `exec_command` invocations; `rm -f` is blocked (use
  `python3 -c "import os; os.unlink(...)"`); `pip` defaults to the
  Aliyun mirror; macOS Python venvs have no bash;
  `/opt/homebrew/bin/loop-memory` (old 0.2.0) is on `PATH`; a `cwd`
  containing a `loop_memory/` checkout shadows the venv's
  site-packages; macOS `/tmp` resolves to
  `/private/var/folders/...` (0.4.10 path-safety helper allow-lists
  `/var/folders/`, `/var/tmp/`, `/tmp/`, `/private/tmp/`,
  `/private/var/folders/`).
