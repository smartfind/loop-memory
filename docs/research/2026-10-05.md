## Window summary

The 2026-09-28 → 2026-10-04 window is dominated by **token and
payload-budget tightening** across the agent-memory stack — a
consistent signal from at least four major projects:

1. **Hindsight v0.10.2 (2026-09-29)** ships "concise extraction
   by default, configurable and synced" as a configurable flag —
   the per-write pipeline default no longer emits verbose free-text
   paragraphs; instead callers get the structured essentials.
   This is the single biggest design signal of the week: the
   agent-memory ecosystem has collectively decided that **the
   recall payload must be capped, not just the index**. Implication
   for Loop Memory: the L0 outline ladder rung (audit 2026-09-13)
   was the right *minimum*, but the L1 / L2 rungs that return full
   `text` / `body` still need a **budget knob** that caps the
   total payload across all hits, so an MCP agent loop can ask
   "give me back ≤ 2400 characters" instead of hand-trimming.

2. **Mem0 v2.2.0 (2026-09-23)** introduces **User Profiles**: a
   structured, always-current JSON summary of one user, shaped by
   a JSON Schema and filled by an LLM from that user's memories.
   This is conceptually the same surface Loop Memory already ships
   (`MemoryStore.list_wiki` + `auto_classification`), but with
   the schema explicitly *user-supplied* per project instead of
   inferred from auto_classification. v2.2.1 (2026-09-25) is a
   pure bug-fix release (Bedrock reasoning-block KeyError, Valkey
   timestamp guard, `pg` as optional peer-dep). Adopting the
   per-project schema is a non-trivial feature (needs a
   `profile_schemas` table, a `profile_runs` queue, an async
   generator loop); **defer to 0.5.0** alongside the recurrence
   counter needed by RecMem.

3. **TencentDB Agent Memory** keeps ticking. `v2.0.2-beta.3` on
   2026-09-21 is the last beta in the v2 line; `v1.0.3` on
   2026-09-22 closes the v1 line. Commits on 2026-09-28 / -09-29
   touch only README_CN refresh + the opencode-v2 provider fix.
   No structural change to the four-asset model (Chat Memory /
   Skill / Wiki / CodeGraph). **Still watchlist-only** per the
   2026-09-13 + 2026-09-20 cycles.

4. **EverOS v1.4.0 + v1.4.1 (2026-09-24)** is the closest peer:
   local-first Markdown-as-truth + SQLite + LanceDB + cascade
   watcher. v1.4.1 is a pure bug-fix (pins `openai<3` to avoid
   the httpx 3.x pre-release that broke every LLM call). Their
   reflection loop (merges episode clusters between sessions) is
   the same shape as our `wiki.ConsolidationEngine`; no
   adoptable pattern we don't already ship.

5. **Honcho v3.2.1 → v3.2.2 (2026-09-24 → 2026-10-01)** adds
   peer-scoped session indexes (28.9ms → 0.15ms on 326k rows) and
   a retry-on-connect exponential-backoff for the Redis client.
   Their deriver prompt rewrite is interesting (one-fact-per-
   conclusion + relative-date resolution per message timestamp),
   but the rewrite lives inside the Honcho service, not at the
   store layer; **defer**.

6. **aiming-lab/SimpleMem (ICML'26)** ships semantic-lossless
   compression with a multimodal extension. 3.8k stars,
   multimodal text/image/audio/video memory, MCP server at
   `mcp.simplemem.cloud`. Heavy stack (embedding model + LLM
   judge + LanceDB) and runs as a managed service — **defer**;
   the *idea* (semantic compression before the payload is emitted)
   is the inspiration for the recall budget cap we adopt this
   cycle.

7. **OpenViking v0.4.23 (2026-10-02)** is a 39k-star "context
   database for AI agents" that unifies Memory + Knowledge + Skills
   into one filesystem. AGPLv3 — not compatible with our MIT
   install. **Defer**. Their tiered-loader (`L0/L1/L2`) is the
   same idea as our existing `recall_hybrid(level=0/1/2)` knob.

8. **zep zep-ingest-v0.3.0 (2026-08-28, pre-window)** added an
   upper bound `<4` on `zep-cloud`; the Python integration
   cap carries into 2026-10-03 with a tightened `<4` floor. Same
   idea as our `cogstate-eng/memory-eternal` SQLite `EBUSY`
   fix; not adoptable for our architecture.

9. **Academic signal** (RecMem ACL2026 Findings, 2026-09-22;
   SimpleMem ICML'26, 2026-10-04) continues to converge on
   recurrence-driven consolidation + semantic compression — the
   same themes the agent-memory OSS stack is shipping. We already
   have the recurrence counter (`memory_signals.recall_count`)
   from 0.4.7; the consolidation trigger and the
   reconstruction-on-demand pattern are deferred to 0.5.0 (3-feature
   lift as noted last cycle).

## Adopt / defer / reject

### Adopted this cycle → `0.4.13`

- **Token / char-budget cap on `recall()`, `recall_paths()`,
  `recall_hybrid()`, `recall_as_of()`** (audit 2026-10-05).
  New `max_chars: int | None = None` parameter caps the *total*
  payload across all returned hits; when the budget is exceeded
  each hit's `text` / `body` / `preview` is truncated to fit
  the per-hit fraction. Default `None` preserves the existing
  payload byte-for-byte. The cap is enforced *after* ranking, so
  the top-scoring hits are always preserved in full; truncation
  only ever shortens the lower-ranked tail. This is the Loop
  Memory take on Mem0 v2.2.0's "concise extraction by default",
  Hindsight v0.10.2's "concise extraction default flag",
  SimpleMem's semantic lossless compression, and MemU's
  per-retrieval token cap. **Source attribution:**
  `vectorize-io/hindsight v0.10.2` "concise extraction by
  default, configurable and synced" (Apache-2.0, 2026-09-29) +
  `aiming-lab/SimpleMem` ICML'26 semantic-lossless-compression
  (Apache-2.0, 2026-10-04) + `mem0ai/mem0 v2.2.0` User Profiles
  shape (Apache-2.0, 2026-09-23).

- **Unify the OpenViking-style `level=0|1|2` tiered-loader knob
  across every recall method** (audit 2026-10-05).
  `MemoryStore.recall_hybrid()` already accepts `level=0/1/2`
  (audit 2026-09-13). `recall()`, `recall_paths()`, and
  `recall_as_of()` now accept the same `level` knob so the
  CLI / HTTP / SDK callers can ask for L0 / L1 / L2 inline
  without routing through `recall_paths()` separately.
  `GET /api/recall?level=0` returns the abstract ladder rung
  inline; `GET /api/recall?level=1` is the default (unchanged);
  `GET /api/recall?level=2` is full text. **Source attribution:**
  `volcengine/OpenViking` tiered-loader (AGPLv3, 2026-10-02)
  — same idea, our MIT-compatible implementation; the *pattern*
  is not copyrightable, only code is. (No code copied.)

### Deferred

- **RecMem recurrence-counter consolidation trigger** (audit
  2026-10-05). RecMem's recurrence counter + reconstruction-on-
  demand pattern needs a recall-hit counter (we ship one in
  0.4.7), a trigger-on-recall hook (no), and a recurrence-driven
  consolidation trigger (no). 3-feature lift; defer to 0.5.0.
- **TencentDB Skill / CodeGraph / Memory-Proxy adoption** —
  watchlist only per the 2026-09-13 + 2026-09-20 + 2026-09-27
  cycles.
- **Mem0 v2.2.0 User Profiles (per-project JSON Schema
  summary)** — needs a `profile_schemas` table +
  `profile_runs` queue + async generator loop; defer to 0.5.0
  alongside the recurrence counter.
- **Honcho peer-scoped session index** — N/A; our
