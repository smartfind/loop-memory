## Window summary

The seven-day window saw **Cognee ship two patch releases** —
v1.5.1 (2026-08-21) and v1.5.2 (2026-08-22) — both themed around
**search relevance tuning for short / ambiguous queries**, **faster
+ more reliable large-file ingestion**, and **stricter input
validation around public API endpoints**. The "short query ranking
tightening" is the liftable pattern this cycle. **Mem0** stayed
silent at v2.0.18 (no new release in window). **Letta** continues
the 0.16.8 freeze (now 14+ weeks). **TencentDB** stayed at
v2.0.1-beta.2; **EverOS** stayed at v1.2.3; **MemOS** shipped
a local-plugin v2.0.16 update but no main-version release.

Three new peer projects crossed the radar this cycle:

- **`agentbrain`** (`2672243194/agentbrain`, Apache-2.0 visible
  but repo shows `NOASSERTION` per the GitHub API — treat as
  unverified license until an explicit `LICENSE` file lands).
  Topics: `agent-memory`, `codex`, `claude-code`, `local-first`,
  `markdown`, `bm25`. v0.4.3 (2026-08-22) introduced
  `agentbrain rules --agent <name> --write` — a CLI that
  appends a three-phase memory-discipline block into client
  rule files (CLAUDE.md / AGENTS.md / Cursor / Trae). **Same
  week we shipped our 0.4.3 cycle; positioning overlap is
  strong.** Their `rules --write` pattern is the liftable item
  (§4 below).
- **`Heimdall`** (`ArihantDeva/heimdall`, MIT, 28 stars). NPM
  package, Swift-side, file-graph indexing with **STRONG /
  WEAK / REBUILT / STALE / REMOVED** labels on recall hits.
  Concept: re-verify every hit against the filesystem at query
  time so a dead path never ranks. Their recall uses
  tree-sitter AST parsing + local embeddings. **Different
  stack** (file-graph vs conversation-graph), so the verdict
  pattern doesn't transfer cleanly; tracked for §5 defer.
- **`MarkMem`** (`MonishKanungo/MarkMem`, Apache-2.0, 7
  stars). Markdown + git-versioned memory + MCP. Same idea as
  our wiki export shape, but with the git diff as the audit
  trail. Defer — body is too small to lift code from, but the
  git-as-audit-trail framing is worth keeping in the back of
  our mind.

**Rejected on licensing or scope**:

- `distill-kura` (MIT but tiny; "writing gated by evidence"

## Material findings

### 1. Cognee v1.5.1 + v1.5.2 — short-query ranking tightening (2026-08-21, 2026-08-22)

- **Source.** Releases `topoteretes/cognee v1.5.1` (2026-08-21)
  and `v1.5.2` (2026-08-22), drawing on PRs in the
  `cognee/search-ranking` and `cognee/ingestion` namespaces.
- **License.** Apache-2.0.
- **Highlights.**
  - **Search relevance tuning for short and ambiguous queries** —
    ranking logic reweights when there are few query terms so
    documents that have been useful before surface more reliably.
  - **Faster + more reliable ingestion** for large uploads and
    bulk imports; clearer progress + per-page error reporting.
  - **Stricter input validation** around public API endpoints to
    prevent malformed requests from causing inconsistent state.
  - **Pagination fix** in dataset views so the newest documents
    do not hide behind a stale offset.
- **Adoption this cycle.** **Short-query ranking tightening is
  adopted.** See `loop_memory/storage/sqlite_store.py::recall`
  — when `len(tokens) <= 2`, an additional `recall_count` weight
  is applied, capped at +30 % so popular memories nudge rather
  than dominate the importance + score multipliers. Pinned by
  5 new cases in `tests/test_short_query.py`.
- **Why this one and not the rest.** The "faster / more reliable
  ingestion" work targets a hosted graph stack we don't have.
  The "stricter input validation" overlaps with our already-pinned
  `scan_secrets.py` + parameterised-SQL surface. The pagination fix
  in dataset views is dashboard chrome — not in our adopt queue
  this cycle. The short-query ranking is small, isolated, and
  measurably improves a real surface that users hit every day
  (the CLI `recall <single word>` path).

### 4. Loop Memory audit — rules installer adopted this cycle

- **Source.** `2672243194/agentbrain v0.4.3` released
  2026-08-22, adding `agentbrain rules --agent <name>
  --write` to install the memory-discipline block into client
  rule files.
- **Adoption.** **`loop-memory rules --agent <codex|claude|hermes|openclaw> --write`**
  ships in this cycle. Targets:

  | `--agent` | Path under cwd |
  | --- | --- |
  | `codex`    | `AGENTS.md`   |
  | `claude`   | `CLAUDE.md`   |
  | `hermes`   | `AGENTS.md`   |
  | `openclaw` | `AGENTS.md`   |
  | `generic`  | `AGENTS.md`   |

  Safety: the discipline block is bracketed by an idempotency
  marker comment; existing user content is **never overwritten**;
  `--force` refreshes the marker span in place without
  touching anything outside it. Pinned by 16 new cases in
  `tests/test_cli_rules.py` covering render, resolve-target,
  install-creates-new-file, append-without-overwrite,
  idempotency, force-refresh, claude-targets-claudemd, and
  print-mode-no-write.
- **Why this matters.** This is the loop-memory adoption
  lever: before this cycle the only way to get a client to
  call `loop-memory recall` was to install the MCP server
  (`loop-memory install-hooks`) and hope the agent chose to
  call it. With `loop-memory rules --write`, the client
  reads the discipline on every prompt and calls
  `recall` automatically — the same shape `agentbrain rules`
  uses. Combined with the existing `install-hooks`, this
  gives us a "wire + discipline" one-two punch.

### 5. Heimdall — verified-hits verdicts (defer, watch)

- **Source.** `github.com/ArihantDeva/heimdall` README +
  recent commits, MIT license, 28 stars.
- **License.** MIT.
- **Decision.** `defer` (continue watching).
- **Pattern of interest.** Heimdall re-verifies every
  recall hit against the filesystem and labels it
  STRONG / WEAK / REBUILT / STALE / REMOVED so the agent
  can act on a STRONG hit without second-guessing. Their
  architecture is file-graph (tree-sitter AST + sqlite +
  local embeddings) — fundamentally different from our
  conversation-graph. Our memories don't have a stable
  per-memory file path to verify (most are conversations,
  not files); the watcher ingests directory paths but the
  conversation itself is in SQLite. Until we ship a
  per-memory path-or-citation surface, the verdict pattern
  has no clean surface to land on. Watch for a v0.2 with
  multi-source memory or a citation field — that's when
  the verdict pattern would transfer.
